THE CASE STUDY

Why climate clustering?

PROJECT OVERVIEW

Weather records are multidimensional. Looking at temperature or rainfall alone may miss combinations of conditions that occur together. Clustering groups observations with similar numerical profiles without needing a predefined target label.

EXPLORATORY NOTES

Questions EDA helps answer

A
Are values missing?

Missingness is measured before filling values so the preprocessing decision is visible.

B
Are scales comparable?

Temperature, rainfall and pressure use different units and ranges; scaling is important for distance-based models.

C
Are there unusual values?

Outliers require review. A rare weather event may be real, so it should not be deleted automatically.

D
Which variables describe climate?

City, State and Date are useful for context, but identifiers are not blindly treated as continuous distance features.

INTERPRETATION

What the model is doing

01
Initialize centroids

K-Means++ seeds candidate cluster centres to spread initial centres apart.

02
Assign and update

Each record is assigned to the nearest centroid, then centroids are updated to cluster means.

03
Repeat to convergence

Assignment and update steps repeat until labels stabilize or the iteration cap is reached.

04
Evaluate internally

Silhouette and Davies–Bouldin describe separation/compactness without using target labels.

04 / HIERARCHICAL CLUSTERING

Hierarchical analysis

Build nested groups by repeatedly merging the closest clusters. Ward linkage favours merges that minimize the increase in within-cluster variance.

i
Why a bounded sample?

A dendrogram on thousands of observations can be expensive and unreadable. This browser demo caps hierarchical training to a representative sample (up to 180 records); this approximation is stated here rather than hidden.

ALGORITHM SUMMARY

Bottom-up grouping

1Start with singletons

Initially, each sampled training observation is its own cluster.

2Measure merge cost

Ward's criterion estimates the increase in within-cluster sum of squares for each candidate merge.

3Merge repeatedly

The lowest-cost pair is joined until the target number of groups remains.

4Read the tree

The merge heights reveal how groups combine at different similarity levels.

Agglomerative clustering has no native out-of-sample predict method. For a like-for-like holdout illustration, this website assigns validation/test rows to their nearest final cluster centroid; report this as an approximation, not as the native algorithm.

05 / EVALUATION & INTERPRETATION

Model comparison

Compare internal metrics and algorithm behaviour. No “accuracy” is reported because there are no ground-truth climate labels.

COMPARISON FRAMEWORK

Quality isn't one number.

Use separation, compactness, cluster sizes and domain interpretability together. Metrics support the judgement; they do not replace climate knowledge.

K-MEANS

Strengths & trade-offs

  • +Fast and scalableWorks well for larger numerical datasets.
  • +Simple cluster assignmentCentroids make new-point assignment straightforward.
  • −Must choose KSensitive to initialization, scale and extreme observations.
  • −Centroid assumptionsMay struggle with irregularly shaped clusters.
HIERARCHICAL

Strengths & trade-offs

  • +Nested structureDendrogram shows how groups merge at different distances.
  • +Linkage flexibilityWard linkage focuses on compact within-cluster groups.
  • −Higher computational costFull dendrograms on large data are expensive.
  • −Greedy mergesEarly merge decisions generally cannot be undone.

CONCLUSION

From climate records to interpretable groups

The project demonstrates an unsupervised workflow: inspect the data, prevent preprocessing leakage, standardize numerical climate variables, discover groups with two methods, and assess cluster structure using internal metrics. A final recommendation should be based on the actual dataset outputs and domain interpretation—not on synthetic demo scores.
